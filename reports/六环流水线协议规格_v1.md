# 六环流水线协议规格 v1.0

**目标**：对话输出从"菜单模式"（素材摊开AI自取）改为"流水线模式"（环环交接，无废弃元素，输出只由上游产物合成）。

**设计者**：Alex（逸翔）定方向："环环相扣，利用每一点，总结出最好的输出"。

---

## 0. 诊断（为什么现在零散）

| 断裂 | 表现 | 根因 |
|---|---|---|
| 数据无主 | 注入的行情/期权/财报被AI按需取用，用不到的闲置 | 注入块与管线环节无映射 |
| 框架是嘉宾不是函数 | blend②"分别审视"无输出格式约束，视角结论形态不可控 | 环②→环③之间无产物交接 |
| 历史对照孤立 | 规则28对账段是"孤立开头段"，结论不参与后续推理置信 | 对账→判断之间无置信修正链 |
| 合成不收敛 | 融合输出允许引入前环没有的信息（新数字/新论据凭空出现） | 环④→环⑤无"禁新信息"约束 |

---

## 1. 六环定义（blend旗舰全量）

每一环：**吃（上游产物+注入槽位）→ 吐（中间产物）**。全部在thinking内部执行，用户只见环6产物。

### 环1 问题解析
- 吃：用户问题 + [用户关注池] + 【历史判断记账】注入
- 吐：①归因四选一（估值/时机/仓位/心理）②维度序列（按裁决权层级排序：质量>价格>时机，再附情绪维度）③账本命中声明（命中标的+核验状态）
- 出口：维度序列决定环2取什么数据；账本命中决定环5是否激活

### 环2 定向取证
- 吃：注入块（带槽位标注）+ 环1维度序列
- 吐：维度→证据包映射。每维度的证据包=该维度最小数据集，**每个证据点必须标功能**（支撑/阈值/风险度量三选一）
- 槽位表（代码层注入时标注，prompt层照单取用）：

| 注入块 | 服务维度 | 功能角色 |
|---|---|---|
| 实时行情（现价/涨跌幅/52周锚） | 质量+时机 | 估值锚/关键位锚 |
| 行业对比（同行PE/中位数） | 质量 | 估值定位 |
| 财报日历 | 质量+时机 | 事件风险阈值 |
| 期权链（IV/Greeks/OI） | 时机+风险 | 波动率定价/仓位结构 |
| VIX情绪 | 情绪 | 逆向指标 |
| 交叉信号池（量能/趋势） | 时机 | 入场/离场触发 |
| 快讯 | 全维度 | 事件证据（带时间戳） |
| 宏观锚（10Y/美元） | 质量+时机 | 贴现率/风险偏好背景 |
| 案例库few-shot | 环6先例 | 结构相似先例证据 |
| 语录库 | 环3署名 | 框架发声（防错闸约束下） |

- 纪律：**映射不上任何维度的注入块=废弃元素**——要么环1补维度，要么代码砍注入（当前全块可映射，无废弃）

### 环3 框架即函数
- 吃：环2证据包 + 视角选择（规则26强制对立）
- 吐：每视角一份中间判断，固定格式：`[视角] 维度=质量 | 判断=X | 置信=0.N | 依据=证据点#编号`
- 硬约束：视角只吃自己维度序列对应的证据包（估值视角不吃时机证据——交叉留给环4）；依据必须引用证据点编号（可溯源）

### 环4 对抗裁决
- 吃：环3全部中间判断
- 吐：①交锋记录（谁攻击谁什么论点+驳倒/幸存，规则26）②冲突裁定（按质量>价格>时机层级，胜者+压倒逻辑一句）③幸存判断清单（带修正后置信）
- 裁定示例：估值视角"贵，置信0.3多" vs 时机视角"关键点突破在即，置信0.6多"→时机赢但前提写明（"估值贵限定仓位，不否定方向"）

### 环5 历史对照（账本命中时激活）
- 吃：环4幸存判断 + 【历史判断记账】+ 机械核验状态（triggered/safe/unknown）
- 吐：置信修正值：维持→信心档不变或+0.5档；翻转→立场重建（规则28三选一）；重立→明说核验不了
- 硬约束：对账结论必须写进最终判断的信心度声明（"较上次判断：维持，信心度中→中高"）——对账不再是无后续的孤立段

### 环6 收敛合成（唯一写正文的环境）
- 吃：环1维度序列 + 环4幸存判断 + 环5置信修正 + 案例库先例
- 吐：最终正文（金样例结构不变）
- **禁新信息律：正文出现的每个数字/每个案例/每条语录必须能在环2证据包或环5账本中找到出处；引入前五环没有的新论据=失败输出**
- 案例固定用法：结构相似先例作为"先例证据"进正文（不是装饰引用）

## 2. balanced三环（标准/深度档简化管线）

- 环A 解析取证 = blend环1+环2（归因+维度序列+证据包）
- 环B 对抗对照 = blend环4+环5（芒格反转检验+账本对照，视角不署名）
- 环C 收敛 = blend环6（禁新信息律同样生效）

短问（规则7简洁档）/讨论档不进流水线——四件套/聊天式直答，零变化。

## 3. 规则栈新增（29号，防撞号已核对现有1-28+QG/R/S/D系列）

**29. 流水线交接纪律（深度/blend档生效）：**
1. 无功能不引用：正文每个数字必须承担功能（支撑结论/失效阈值/风险度量三选一），纯展示数字不出现
2. 署名纪律：大师名字只出现在论据后的溯源标注（`[视角]`），禁止"XX认为"开头的独立发言段
3. 冲突必过裁定：多空对置的每对冲突写明胜负与前提（按质量>价格>时机层级），和稀泥=失败
4. 禁新信息律：结论与行动计划只由前文已出现的证据合成，禁止末段引入新数字/新论据
5. 账本命中标的：信心度声明必须含与上次判断的对照结果（维持/翻转/重立）

## 5. 验收判据（四查，全部机械可测）

1. **署名查**：正文中"（芒格|巴菲特|利弗莫尔|段永平|索罗斯|马斯克|格雷厄姆|马克斯|费雪|塔勒布|林奇）认为/说/指出"开头的独立发言段=0；`[视角]`格式署名≥1处（blend深度档）
2. **功能查**：抽取正文中所有百分比/价格数字，逐个检查所在句含功能词（支撑/失效/触发/阈值/止损/仓位/目标/风险之一）——裸数字率<10%
3. **裁决查**：深度/blend档正文含【裁决】表且质量/价格/时机三字段非"存疑"占位
4. **对账查**：注入含【历史判断记账】且问题涉及记账标的时，正文含对账特征（"上次/维持/翻转/重立"任一）且信心度声明含对照结果

跑法：`node scripts/test_pipeline_acceptance.js`——内置固定样例（正例/负例各1）+支持传文件测真实输出。

## 6. 风险与边界

- thinking变长：六环交接会增加blend思考量，blendMaxTokens=16384已给足；balanced三环增量很小
- 禁新信息律误伤：免责声明/风险边界语不算"信息"（无判断功能），脚本排除
- 前缀缓存：槽位标注只加在注入块（每轮变化区），systemPrompt规则栈稳定追加29后首次断缓存一次（成本≈0.04元），之后恢复
- 与5队资产的关系：案例库/语录库/仲裁机制是**素材资产**，六环是**运行模式**——环2槽位表与环6先例槽位正是这些资产的消费口，两者互补不冲突
